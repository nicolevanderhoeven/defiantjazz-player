# Evidence board (MCP App)

A small MCP server for the local stack. Its one tool, `show_evidence_board`, takes the timeline, clues, people and open questions an investigating agent has found so far and draws them as an interactive board in the chat (an [MCP App](https://modelcontextprotocol.io/extensions/apps)). Hosts with no interactive views get the same findings as text. The board knows nothing about the case: it shows only what the agent passes in.

The board has two lanes, so the split between what the investigator knows and what only the player holds is something you can see. **From the telemetry** is what the agent found by querying the data; **From your leads** is what the player told the agent from the leads they opened in the web app (the agent cannot see those unless the player shares them). Every person, timeline entry and clue takes an optional `origin` of `telemetry` (the default, so older calls still work) or `lead`, shows a small Telemetry or Lead tag, and sits in its lane. A person named in both lanes (same name, any case) gets one card, in the telemetry lane. Open questions sit below both lanes. Red string may cross lanes; that crossing is the point. The text fallback groups by the same two lanes. `renderBoard(doc, root, input, art, { lanes: ["telemetry"] })` draws just one lane (dropping items from the others), for a page with no leads.

It is drawn as an investigator's cork board in a wooden frame: in each lane people are pinned Polaroids, clues are pinned index cards, the timeline is a sheet of paper with a pin at each entry, open questions are sticky notes, and the case title is a label. Red string runs from each person to the timeline entries and clues that mention them (whole names only, any case). Click a clue or timeline entry to open its detail and source; click a person to light up their string and dim everything that does not mention them (click them again, the chip, or press Escape to clear). The string is decoration: every card also says in text who it mentions, every person says how many entries and clues name them, and a status line reads out the selection. There is no separate list mode; the board is a single column at narrow widths, is made of real headings, lists and buttons, and follows the host's light or dark theme.

The artwork comes from the public web app, shrunk and inlined into the view (`view/art/`), using only pictures the game shows a player before an accusation. A person's portrait is pinned when their first name is Agnes, Bertram or Clement (anyone else gets an initials card). The agent can pin pictures with `scene` and `scenes` (up to six, no repeats): `break-room` (the web app's Break Room scene), `power-cut` (`scene-power-cut`, the blackout panel), `break-room-camera` (`scene-break-room-camera`, Break Room 2's security camera panel) and `flyer` (`flyer-kipsake`, the Kipsake advert shown at the start). Unknown names show nothing; the text fallback carries no images.

- `server.mjs`: the MCP server (streamable HTTP, `/mcp`, port 8001), `board.mjs`: the input schema and the text fallback.
- `view/`: the board itself. `node build.mjs` bundles it with the MCP Apps SDK into one self-contained `dist/view.html`.
- `npm test`: builds, then tests the tool schema, text fallback, escaping of agent text and the view's interactions.
- To look at it in a browser with the SDK's own host bridge: `PORT=8001 node server.mjs`, then `node test/harness/serve.mjs` and open <http://127.0.0.1:8099/> (`?theme=dark` for a dark host, `?many=1` for a crowded board, `WIDTH=340 node test/harness/serve.mjs` for a narrow chat pane). This uses sample data, not the case.
